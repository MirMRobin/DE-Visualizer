Research data and figure studio

This browser-based workspace profiles a source file, recommends visual forms from its data structure and your stated question, and exports a figure together with the data and settings used to produce it.

Scientific scope. Recommendations are transparent, rule-based suggestions. The tool does not infer scientific meaning, impute missing values, perform statistical tests, or establish that a visualization supports a research claim. Inspect extracted values and figure settings against the source.

1. Load a source

Use one file at a time or paste text into the source field. The supported browser parsers are bundled with the project so spreadsheet, Word, and PDF parsing can run locally.

2. Review the profile

The profile reports observation and field counts, numeric, categorical, and mixed fields, missing cells, category levels, and exact duplicate rows. Numeric fields also show minimum, quartiles, median, maximum, mean, and sample standard deviation. Profiling runs in a Web Worker where the browser permits it. Empty cells are treated as missing; strings such as “NA” are not assumed to be missing. Missing values are excluded from calculations when a figure requires numeric values; no imputation or row removal is applied. Duplicate records stay in the dataset. Oversized sources are capped at 50,000 rows and 1,000,000 cells, and the profile reports when data was capped.

Image OCR is an optional text-extraction action. The first use downloads the OCR engine and English language data from a public CDN; the selected image or PDF stays in the browser. OCR may confuse symbols, labels, or decimal points. OCR does not convert plotted lines or bars into source data.

3. Pick a figure and configure it

The ranked catalog includes line and area trends, scatter and bubble plots, category and grouped bars, histograms, empirical cumulative distributions, box plots, correlation matrices, Pareto charts, image intensity maps, data tables, concept maps, and process sequences.

Recommendations use detected field types, field count, category structure, and your chosen question. Select the horizontal and vertical fields, optional series group, aggregation, palette, title, axis labels, and output dimensions. If a chart shows a limited point sample for responsiveness, the figure caption identifies that fact; data exports retain the full imported rows.

4. Export the figure and its evidence

  • SVG: editable vector artwork; best for suitable journal or presentation workflows.
  • PNG 2× / 4×: high-resolution raster output at the chosen figure dimensions.
  • Data CSV / TSV / JSON / Excel: the imported or extracted rows for independent review.
  • Figure JSON: figure configuration, chart option, source summary, and data for reproducibility.
  • HTML: a portable figure report; Markdown documents source and settings.
  • Mermaid / OPML: structure exports for mind maps and process outlines.
Interpretation stays with the researcher. Correlations are descriptive Pearson coefficients with pairwise-complete numeric values. No confidence intervals, hypothesis tests, causal claims, or model assumptions are inferred. Verify units, transformations, sampling, and aggregation before publication.

5. Build a reviewable research workflow

After profiling data and configuring a figure, open Research workflow. The plan is generated from the current source profile, selected research purpose, and figure fields. It prompts the researcher to verify extraction, define the observation unit and study design, review missing and duplicate records, and document transformations and statistical methods performed elsewhere.

Download a JSON record for structured reuse or a Markdown plan for a manuscript folder. Uploaded files receive a local SHA-256 checksum when browser support permits; pasted or edited data is identified as such. The record includes detected profile signals, figure configuration, chart-selection rationale, researcher notes, and the self-reported review checklist. Checklist ticks are not machine-verified. Keep the original data and any code needed to reproduce analyses.

Workflow boundary. The plan is a transparent checklist, not an automated protocol, data-cleaning engine, ethics review, statistical test, or scientific validation. Statistical conclusions must come from appropriate methods applied to the study design.

Privacy and browser requirements

Uploaded files are processed in the active browser page and are not posted to an application server. OCR is the one network-assisted feature: its engine and English language data are fetched on demand. For PDF workers and OCR, use the published GitHub Pages site or serve the project from a local web server; direct file:// access may be restricted by browser worker security.

For a local preview, run python3 -m http.server 8000 from the project folder and open http://localhost:8000.
